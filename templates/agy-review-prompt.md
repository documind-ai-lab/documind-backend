현재 GitHub PR diff를 MVP 병합 가능 여부 판단 관점으로 검토해주세요.

중요:
- 파일을 수정하지 마세요.
- 명령어를 실행하지 마세요.
- 커밋하지 마세요.
- 리뷰 코멘트만 한국어로 작성하세요.
- 현재 PR의 목적과 범위를 우선 기준으로 삼으세요.
- 이상적인 운영/확장성 개선과 현재 PR의 병합 차단 문제를 구분하세요.

검토 기준:
- 요구사항 충족 여부
- 버그 가능성
- 아키텍처/레이어 경계 위반
- 테스트/검증 부족
- 보안/권한/데이터 처리 리스크
- 불필요한 복잡도
- 문서/템플릿 표현의 모호함
- 병합 전 확인 사항

병합 차단 기준:
- 현재 PR diff 안의 명백한 오류
- 문서나 코드 내부의 직접적인 모순
- 작성된 API 계약대로 구현하면 실패할 가능성이 높은 항목
- MVP에서 즉시 악용 가능한 보안/권한/데이터 처리 취약점
- 저장소의 기존 결정사항과 충돌하는 항목

후속 이슈 기준:
- 운영 환경 하드닝
- 대규모 트래픽 대비
- 비동기 아키텍처 전환
- 오브젝트 스토리지 전환
- 고급 보안 스캔
- 부하 테스트
- MVP 이후 확장성 개선

리뷰 종료 기준:
- 병합 차단 기준에 해당하지 않는 의견은 후속 이슈나 참고 의견으로 분류하세요.
- 후속 이슈나 참고 의견만 남아 있다면 병합 판단에 "추가 병합 차단 항목 없음"이라고 작성하세요.
- 같은 성격의 개선 제안을 반복해서 병합 차단 항목으로 올리지 마세요.

출력 형식:
1. 병합 차단
2. 후속 이슈
3. 참고 의견
4. 병합 판단

출력 제한:
- 위 4개 섹션만 작성하세요.
- 작업 요약, 요청 조건 요약, 모델의 수행 방식 설명은 작성하지 마세요.
- 파일을 수정하지 않았다는 설명이나 명령어를 실행하지 않았다는 설명을 작성하지 마세요.
- 섹션 밖의 마무리 문장이나 추가 요약을 작성하지 마세요.
