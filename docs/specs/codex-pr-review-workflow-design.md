# Codex PR 리뷰 워크플로우 설계

## 배경

DocuMind 백엔드는 이슈, 브랜치, PR, 검증, 병합, 이슈 종료 순서로 작업한다. 외부 AI 리뷰 도구는 사용하지 않기로 결정했으므로, PR 리뷰 기록과 병합 판단은 Codex가 직접 수행하고 GitHub PR Conversation에 남긴다.

이 문서는 PR 생성 후 Codex 리뷰 결과, 리뷰 반영 결과, 병합 판단을 일관된 형식으로 남기는 운영 워크플로우를 정의한다.

## 목표

- PR 생성 후 Codex 리뷰 1회를 필수 게이트로 둔다.
- Codex 리뷰 결과를 GitHub PR 댓글로 남긴다.
- 리뷰 결과에 대응한 반영 결과를 GitHub PR 댓글로 남긴다.
- 더 이상 병합 차단 항목이 없을 때 병합 진행 판단 댓글을 남긴다.
- PR 병합 후 연결 이슈를 닫고 Project 상태를 `Done`으로 변경한다.

## 범위

포함한다.

- PR 생성 이후 리뷰와 병합까지의 운영 절차
- Codex 리뷰, 리뷰 반영, 병합 판단의 추론 수준 기준
- PR 댓글 템플릿
- 병합 차단 항목 기준
- 이슈와 Project 완료 처리 기준

포함하지 않는다.

- 외부 AI 리뷰 도구 연동
- GitHub Actions로 리뷰 댓글 존재 여부를 강제하는 자동 check
- 리뷰 결과를 기계적으로 파싱해 병합을 차단하는 기능
- 여러 저장소에 동시에 적용하는 조직 공통 workflow

## 추론 수준 정책

작업 단계별 추론 수준은 다음으로 고정한다.

| 단계 | 기준 |
| --- | --- |
| 일반 구현 | 높음 |
| Codex 리뷰 | 매우 높음 |
| 리뷰 반영 구현 | 높음 |
| 테스트/검증 | 높음 |
| 병합 판단 | 매우 높음 |

Codex 리뷰는 문제를 찾는 단계이므로 매우 높음 기준으로 수행한다. 병합 판단은 `develop` 반영 여부를 결정하는 단계이므로 Codex 리뷰와 같은 매우 높음 기준으로 수행한다. 리뷰 반영 구현은 이미 수정 범위가 좁혀진 상태이므로 높음 기준으로 수행한다.

## 전체 흐름

```text
이슈 생성
→ 작업 브랜치 생성
→ 구현과 로컬 검증
→ PR 생성
→ Codex 리뷰 실행
→ Codex 리뷰 결과 PR 댓글 게시
→ 리뷰 결과 반영
→ 리뷰 반영 결과 PR 댓글 게시
→ 병합 판단
→ 병합 진행 판단 PR 댓글 게시
→ PR 병합
→ 연결 이슈 close
→ Project Done
```

## Codex 리뷰 필수 조건

PR 생성 후 Codex 리뷰 1회는 필수다.

Codex 리뷰는 PR diff 기준으로 수행한다. 리뷰 대상은 최신 PR diff이며, 리뷰 전 다음을 확인한다.

- base branch가 `develop`인지 확인한다.
- PR head branch가 작업 브랜치인지 확인한다.
- 연결 이슈가 PR 본문에 `Refs #번호` 형태로 기록되어 있는지 확인한다.
- 로컬 검증 결과가 PR 본문에 기록되어 있는지 확인한다.

추가 커밋이 올라간 경우 Codex 리뷰 재실행은 필수가 아니다. 다만 기존 Codex 리뷰의 병합 차단 항목을 해결하기 위한 변경이 크거나, API 계약, 권한, 데이터 정합성, 마이그레이션에 영향을 주는 변경이면 병합 판단 단계에서 추가 Codex 리뷰를 요구할 수 있다.

## Codex 리뷰 기준

Codex 리뷰는 다음 항목을 우선순위로 본다.

1. 병합 차단
   - 런타임 오류 가능성
   - API 계약 불일치
   - 데이터 손상 가능성
   - 권한 검증 누락
   - 보안상 즉시 악용 가능한 결함
   - 테스트가 통과해도 실제 동작이 깨지는 회귀
   - 이슈 목표와 명백히 다른 구현

2. 후속 이슈
   - 현재 PR 목표 밖의 개선 사항
   - 운영 환경 하드닝
   - 대규모 트래픽 대비
   - 추가 관측성, 알림, 운영 편의성
   - MVP 이후 확장성 개선

3. 참고 의견
   - 이름, 문서, 구조, 테스트 가독성 개선 제안
   - 병합을 막지 않는 유지보수 의견

4. 병합 판단
   - 현재 상태로 병합 가능한지 판단한다.
   - 병합 차단 항목이 있으면 `병합 보류`로 판단한다.
   - 병합 차단 항목이 없으면 `추가 병합 차단 항목 없음`으로 판단한다.

## PR 댓글 템플릿

### Codex 리뷰 결과

Codex 리뷰 후 다음 형식으로 PR 댓글을 남긴다.

```md
## Codex 리뷰 결과

### 1. 병합 차단
없음

### 2. 후속 이슈
없음

### 3. 참고 의견
없음

### 4. 병합 판단
추가 병합 차단 항목 없음
```

병합 차단 항목이 있으면 파일 경로와 이유를 포함한다.

```md
## Codex 리뷰 결과

### 1. 병합 차단
- `src/example.ts`: 요청 검증 실패 시 400이 아니라 500을 반환할 수 있습니다. API 계약의 오류 응답과 충돌합니다.

### 2. 후속 이슈
없음

### 3. 참고 의견
없음

### 4. 병합 판단
병합 보류. 병합 차단 항목을 반영한 뒤 다시 확인해야 합니다.
```

### Codex 리뷰 반영 결과

리뷰 결과를 반영한 뒤 다음 형식으로 PR 댓글을 남긴다.

```md
## Codex 리뷰 반영 결과

반영한 항목:
- `src/example.ts` 오류 응답을 API 계약에 맞게 400으로 수정했습니다.

반영하지 않은 항목:
- 없음

추가 확인:
- `npm run test:e2e -- example.e2e-spec.ts`
- `npm run lint`
```

반영하지 않은 항목이 있으면 이유를 명확히 적는다.

```md
반영하지 않은 항목:
- 운영 알림 추가는 현재 PR 목표 밖이므로 후속 이슈로 분리합니다.
```

### 병합 진행 판단

병합 직전 매우 높음 기준으로 마지막 판단을 수행하고 다음 형식으로 PR 댓글을 남긴다.

```md
## 병합 진행 판단

Codex 리뷰 결과와 반영 내용을 확인했습니다.

현재 추가 병합 차단 항목이 없어 병합 진행합니다.
```

병합을 진행하지 못하면 다음 형식으로 남긴다.

```md
## 병합 진행 판단

Codex 리뷰 결과와 반영 내용을 확인했습니다.

아래 항목이 남아 있어 병합을 보류합니다.

- `npm run test:e2e` 실패 원인 확인 필요
```

## 병합 기준

PR은 다음 조건을 모두 만족해야 병합한다.

- PR 본문에 연결 이슈가 `Refs #번호`로 기록되어 있다.
- 로컬 검증 결과가 PR 본문 또는 PR 댓글에 기록되어 있다.
- Codex 리뷰 결과 댓글이 있다.
- 병합 차단 항목이 없거나 모두 반영 완료되었다.
- Codex 리뷰 반영 결과 댓글이 있다.
- 병합 진행 판단 댓글이 있다.
- PR이 `develop` 대상으로 열려 있다.
- 병합 가능 상태다.

## 완료 처리

PR 병합 후 다음을 처리한다.

1. PR 상태가 `MERGED`인지 확인한다.
2. 연결 이슈가 열려 있으면 완료 코멘트를 남기고 닫는다.
3. GitHub Project 상태가 `Done`인지 확인한다.
4. Project 상태가 `Done`이 아니면 `Done`으로 변경한다.
5. 원격 작업 브랜치 삭제를 확인한다.
6. 로컬 작업 브랜치가 남아 있으면 정리한다.

## 실패 처리

Codex 리뷰 결과 병합 차단 항목이 있으면 바로 병합하지 않는다.

처리 순서는 다음이다.

1. 병합 차단 항목을 작업 항목으로 정리한다.
2. 현재 PR 범위 안에서 반영 가능한 항목을 수정한다.
3. 범위 밖 항목은 후속 이슈로 분리한다.
4. 반영 결과 댓글을 남긴다.
5. 병합 판단을 다시 수행한다.

로컬 검증을 실행하지 못한 경우에도 병합 판단에서 확인한다. 실행하지 못한 검증이 핵심 동작을 증명하는 데 필요하면 병합을 보류한다.

## 문서 반영 대상

이 설계가 승인되면 다음 문서에 반영한다.

- `docs/workflow/backend-loop.md`
- `.github/pull_request_template.md`

`backend-loop.md`에는 Codex 리뷰 루프와 병합 판단 단계를 추가한다. PR 템플릿에는 Codex 리뷰 결과, Codex 리뷰 반영 결과, 병합 진행 판단 댓글이 필요하다는 체크 항목을 추가한다.
