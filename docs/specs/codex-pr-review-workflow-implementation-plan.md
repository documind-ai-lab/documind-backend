# Codex PR 리뷰 워크플로우 구현 계획

## 배경

`docs/specs/codex-pr-review-workflow-design.md`에서 Codex가 PR 리뷰 결과, 리뷰 반영 결과, 병합 판단을 GitHub PR 댓글로 남기는 운영 흐름을 정의했다.

이 문서는 해당 설계를 실제 백엔드 작업 루프와 PR 템플릿에 반영하기 위한 작업 순서를 정의한다.

## 목표

- `docs/workflow/backend-loop.md`에 Codex 리뷰 루프를 추가한다.
- `.github/pull_request_template.md`에 Codex 리뷰와 병합 판단 체크 항목을 추가한다.
- PR 템플릿 점검 섹션명을 `작업 점검`으로 통일한다.
- 병합 관련 용어를 `병합`으로 통일한다.
- 리뷰와 병합 판단의 추론 수준을 문서에 명시한다.

## 작업 순서

### 1. 백엔드 작업 루프 문서 반영

`docs/workflow/backend-loop.md`의 리뷰 단계를 `리뷰와 병합` 기준으로 정리한다.

추가할 내용은 다음이다.

- PR 생성 후 Codex 리뷰 1회 필수
- Codex 리뷰 결과 댓글 작성
- 리뷰 반영 결과 댓글 작성
- 병합 진행 판단 댓글 작성
- Codex 리뷰와 병합 판단은 매우 높음 기준으로 수행
- 리뷰 반영 구현과 검증은 높음 기준으로 수행

### 2. 완료 처리 문서 정리

`docs/workflow/backend-loop.md`의 완료 처리에서 다음을 명확히 한다.

- PR 상태가 `MERGED`인지 확인
- 연결 이슈 close
- GitHub Project 상태 `Done` 확인
- 원격과 로컬 작업 브랜치 정리

### 3. PR 템플릿 반영

`.github/pull_request_template.md`에서 다음을 변경한다.

- 점검 섹션명을 `작업 점검`으로 변경
- 병합 관련 용어를 `병합`으로 변경
- Codex 리뷰 결과 댓글 필요 항목 추가
- Codex 리뷰 반영 결과 댓글 필요 항목 추가
- 병합 진행 판단 댓글 필요 항목 추가

### 4. 검증

문서 변경 후 다음을 확인한다.

- 금지 표현과 미완성 표현 검색 결과가 없는지 확인
- 이전 점검 섹션명이 남아 있지 않은지 확인
- 이전 병합 관련 용어가 남아 있지 않은지 확인
- `git diff --check` 통과

## 완료 기준

- Codex 리뷰 워크플로우가 백엔드 개발 루프에 반영되었다.
- PR 템플릿에서 리뷰 댓글과 병합 판단 댓글을 확인할 수 있다.
- 금지 표현과 미완성 표현이 남아 있지 않다.
- 문서 변경 검증 결과가 커밋과 PR에 기록된다.

## 남은 리스크

GitHub Actions로 Codex 리뷰 댓글 존재 여부를 강제하지 않으므로, 당분간 운영 규칙 기반으로 관리한다.
