# 커밋 메시지 컨벤션

## 목적

DocuMind 백엔드 저장소의 커밋 메시지는 작업 의도, 판단 근거, 검증 결과, 남은 리스크를 한국어로 남기는 것을 기준으로 한다. 커밋 메시지는 변경 파일 목록을 반복하는 설명이 아니라, 이후에 PR과 이슈를 다시 볼 때 왜 그렇게 결정했는지 확인할 수 있는 짧은 기록이어야 한다.

## 제목 형식

커밋 제목은 한국어 Conventional Commit 형식을 사용한다.

```text
<type>: <한국어 제목>
```

예시는 다음과 같다.

```text
feat: Project 생성 API 구현
fix: 보관된 프로젝트 복원 충돌 처리 수정
test: Project API PostgreSQL 통합 테스트 구성
docs: 커밋 메시지 컨벤션 문서화
```

사용하는 `type`은 다음을 기본으로 한다.

- `feat`: 기능 추가
- `fix`: 버그 수정
- `test`: 테스트 추가 또는 수정
- `docs`: 문서, 템플릿, 가이드 변경
- `refactor`: 동작 변경 없는 구조 개선
- `chore`: 설정, 정리, 운영 작업
- `ci`: GitHub Actions, CI/CD 작업

## 본문 형식

커밋 본문은 필요한 경우 다음 섹션을 사용한다.

```md
배경:
왜 이 변경이 필요한지 적는다.

판단:
선택한 방식과 이유를 적는다.

검증:
- 실제 실행한 명령이나 확인한 내용을 적는다.

남은 리스크:
아직 못 한 검증이나 주의할 점을 적는다.
없으면 `없음`이라고 적는다.
```

작은 문서 수정처럼 본문이 과한 경우에는 제목만 사용할 수 있다. 다만 PR에 들어가는 작업 커밋은 가능한 한 `배경`, `판단`, `검증`, `남은 리스크`를 남긴다.

## 작성 예시

```md
test: Project API PostgreSQL 통합 테스트 구성

배경:
Project API가 실제 PostgreSQL에서도 HTTP API와 Prisma adapter를 통해 생성, 조회, 수정, 보관, 복원 흐름을 검증할 수 있어야 합니다.

판단:
실제 DB 주소와 비밀번호는 `.env`에만 두고 저장소에는 남기지 않습니다.
개발자 환경마다 `DATABASE_URL` 준비 여부가 다르므로 기본 통합 테스트는 skip 가능하게 두고, 실제 DB 검증은 `RUN_DB_INTEGRATION=true`일 때만 실행합니다.

검증:
- `npm run test:integration`
- `npm run typecheck`
- `npm run lint`
- `npm test`

남은 리스크:
실제 `.env`가 없는 환경에서는 `RUN_DB_INTEGRATION=true npm run test:integration`을 실행하지 못합니다.
```

## 작성 명령 예시

여러 줄 커밋 메시지는 파일로 작성한 뒤 `-F` 옵션으로 커밋한다.

```bash
git add <변경 파일들>
git commit -F /tmp/documind-commit-message.md
```

이미 만든 최신 커밋의 메시지만 수정할 때는 다음처럼 실행한다.

```bash
git commit --amend -F /tmp/documind-commit-message.md
```

이미 원격 PR 브랜치에 push한 커밋을 amend했다면 다음처럼 안전하게 갱신한다.

```bash
git push --force-with-lease origin <브랜치명>
```

## 금지 항목

커밋 메시지에는 다음 문구를 넣지 않는다.

- `Generated by Codex`
- `Co-authored-by: Codex`
- `Created with ChatGPT`
- `AI-assisted`
- `Constraint:`
- `Rejected:`
- `Confidence:`
- `Scope-risk:`
- `Directive:`
- `Tested:`
- `Not-tested:`

영어 trailer 형식이 필요한 상황이라도 이 저장소에서는 한국어 섹션형 본문을 우선한다.

## 기존 문서의 과거 예시

일부 오래된 구현 계획 문서에는 영어 trailer 중심의 커밋 예시가 남아 있을 수 있다. 해당 예시는 과거 작업 기록으로만 보고, 새 커밋을 작성할 때는 이 문서의 기준을 따른다.
